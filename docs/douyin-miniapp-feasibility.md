# 抖音小程序 + 衣橱 + ComfyUI 可行性结论

> 状态：调研结论，未开始实现。所有「结论」列的事实均来自抖音开放平台官方文档正文（2026-11-22 抓取），
> 来源路径随条目标注；未标注来源的属于推断，已写明「推断」。

## 1. 抖音侧硬约束

| 问题 | 结论 | 官方来源 |
| --- | --- | --- |
| 个人主体能否注册并上架小程序 | 能。六阶段：注册入驻 → 创建 → 开发 → 主营类目 → 备案 → 发布。需本人身份证、年满 18 周岁 | `/zh-CN/mini-app/introduction/personalminiprogramguide` |
| 个人主体能否在小程序内收费 | **不能**。交易能力接入规范明文「不支持个人主体小程序接入」 | `/zh-CN/mini-app/operation/management/specification/trade` |
| 企业主体收费的额外成本 | 类目准入（可开放/邀约开放）+ 按类目缴保证金 + 支付进件 + 结算账期 T+N（默认支付后 7 天）+ 支付手续费 0.6% | 同上；`/zh-CN/mini-app/open-capacity/business-monetization/guaranteed-payment/introduction` |
| 个人主体能否「看广告解锁」 | 能，流量主对个人开发者开放；但**激励视频/插屏/视频流广告位都要求前一日 DAU > 50** | `/zh-CN/mini-app/open-capacity/business-monetization/publisher/publisher` |
| 个人主体流量主能否结算 | 能，月结、确认账单后提现，平台代扣个税 | `/zh-CN/mini-app/open-capacity/business-monetization/publisher/invalid` |
| AI 试穿归哪个类目 | 工具 / AI工具。**定向准入**（需填内测申请表），且个人主体**只能调用第三方算法服务**，须提交第三方《互联网信息服务算法备案》（生成合成类）截图 + 公示内容 + 主体与服务方的合同 | `/zh-CN/mini-app/operation/service-category/available-service-categories` |

由此推出的产品边界：

1. **收费必须企业主体**。个人主体下「自己充值」这条路不存在，不是难，是规则上关闭。
2. **广告解锁有冷启动死结**：DAU > 50 才能建广告位，所以上线首期只能免费额度 + 等 DAU。
3. **算法备案是硬门槛**：用境外模型（如 gpt-image-2）无法满足「第三方算法备案」要求。必须换成国内已备案的生成合成类服务（混元、MiniMax、火山方舟等），并向服务商索取备案号与公示链接——这一步要以实际备案公示为准，不能口头承诺。
4. **服务器域名需备案**：小程序 request 合法域名必须是已 ICP 备案的 https 域名。本地开发可关校验，上线不行。

## 2. 橱窗 / 店铺商品数据

- 抖音开放平台侧没有「读取任意博主橱窗商品」的公开能力。相关能力是**精选联盟 API**，`buyin/kolMaterialsProductsSearch` 等接口需要**达人/抖客授权**（`https://op.jinritemai.com/docs/api-docs/61/1725`，实测可访问，接口目录里该条注明「需达人/抖客授权」）。
- 电商插件 / 电商行业组件在小程序侧标注「即将废弃」。
- 因此「选博主橱窗 → 加进我的衣橱」**不能靠官方接口自动完成**。可行的三条替代：
  1. 用户手动添加：上传/拍照商品图，服务端做品类与主色识别后入库（无需任何授权，最稳）。
  2. 用户粘贴商品链接/口令：需要抖客授权才能解析，个人主体基本拿不到。
  3. 预置示例商品库 + 用户自建衣橱：先跑通搭配与生成，数据来源后置。

## 3. ComfyUI 与本机能力

实测环境：RTX 5060 Laptop，**8151 MiB 显存**（Blackwell sm_120，需 CUDA 12.8+ 的 PyTorch）；本机**未安装 ComfyUI**、未安装 torch；the image service 的 ComfyUI 连接为空。`torch 2.10.0+cu128-cp313-win_amd64` 官方轮子存在，Blackwell 可跑。

试穿模型取舍（均为真实文档参数）：

| 方案 | 显存 | 商用许可 | LoRA 生态 | 多件搭配 |
| --- | --- | --- | --- | --- |
| FASHN VTON v1.5（972M，像素空间无掩码，支持平铺商品图） | 官方未公布；972M bf16 + DWPose + parser，**推断可落在 8GB**，未实测 | **Apache-2.0，可商用** | 无（非 SD 基座） | 需串联（先 tops 再 bottoms） |
| CatVTON（SD1.5 inpaint，899M） | < 8GB @1024×768 fp16（官方） | **CC BY-NC-SA 4.0，禁商用** | 有（SD1.5 LoRA） | 需串联 |
| FLUX Fill / Qwen-Image-Edit + LoRA | 12GB+ 起 | 视基座 | 丰富 | 一次多件 |

结论：**8GB 上想「加 LoRA」和「商用」二者不可兼得**。要 LoRA 就得回到 SD1.5（不可商用）或上云 GPU。

## 4. 推荐路线（待确认）

分三阶段，每阶段都能独立验收：

1. **先做能上架的形态**：个人主体 + 工具/AI工具类目（定向准入需申请）+ 免费额度 + 手动衣橱。生成后端换国内已备案服务，满足算法备案要求。这一阶段验证「抖音里能不能跑起来」。
2. **再解决效果**：本机装 ComfyUI + FASHN VTON v1.5，跑通「人物 + 平铺商品图 → 上身图」真实链路并测显存占用与耗时；效果不达标再评估云 GPU。
3. **最后解决变现**：DAU 过 50 接激励视频；要收费则注册企业主体、走交易准入与支付进件。

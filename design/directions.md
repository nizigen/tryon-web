# 试衣间设计初稿

状态：三方向尚未获得用户选择。本目录只交付设计选择板与预览，不实现业务 UI。用户须在对话中选择后，主任务才进入业务界面。

## 共同输入与约束

- 场景：单人、中文、静态图片虚拟试衣工作台，最常用的素材上传、类别、引擎与试穿入口集中首屏。
- 比较基准：桌面 1440 × 900，窄屏目标 375 × 812；使用系统无衬线字体，无外部字体或框架。
- 范围：人物照片、单件衣物、上装/下装/连衣裙、Decart/OpenAI 兼容选项、原图/结果对照、结果下载入口、当前会话历史空状态。
- 资产：没有用户真实照片、官方品牌标识或已生成结果。不借用原插件资产；上传区和结果均为诚实空状态。Decart/OpenAI 仅为文字接口名称，无品牌视觉复刻或能力声明。
- 原生浏览器能力已足够：file input + URL.createObjectURL + CSS Grid + query 参数变体 + iframe 缩放，无依赖安装。
- 预览上传上限 20 MiB 是防止展示页大文件阻塞的局部限制，不作为未来生产接口的契约；生产界限由项目规范单独确定。

## 六张方向卡

| 候选 | 骨架与具体规则 | 主角素材 | 胆量与内容来源 |
| --- | --- | --- | --- |
| A 摄影工作台 | 左素材、中画布、右设置三栏；黑白细线；摄影接触样张式平视组织 | 用户本地照片；未上传时展示真实空框 | 三栏同屏降低反复跳转，来自人物、衣物、结果三种工作对象 |
| A2 参数先行 | 交换两侧职能，左设置、右素材；沿用白底黑字 | 同上 | 让先选类别与引擎的流程更顺手 |
| B 暗色试衣室 | 深灰外壳、偏暗中央画布、两侧轻工具；青绿仅给动作和选中状态 | 深灰结果画布与用户照片 | 最大视觉资源分给结果，来自试穿后检查衣物边缘和形态的需求 |
| B2 合并工具架 | 两栏骨架；左侧素材与设置纵向合并，右侧完整宽画布 | 同上 | 给结果更多横向空间，接受页面纵向增长 |
| C 分步试衣台 | 左侧连续准备步骤；右侧原图/结果并排；浅灰底、橘色主动作 | 原图与结果双幅 | 步骤编号只用于真实顺序，来自上传人物→上传衣物→设置试穿的操作链 |
| C2 上下对照 | 保留左步骤，右侧原图/结果上下组织 | 同上 | 宽图单幅观看更舒适，接受较高画布 |

以上为任务约束内的自主构图，不声称参考了未实际打开的设计师作品、网站截图或风格样张。三套主骨架由用户直接指定，本轮没有伪造“随机轮盘”或现实参考核验。

## 交互与信任边界

- 上传仅用浏览器对象 URL；仅支持 JPEG、PNG、WebP。图片不发往服务器，不写 localStorage 或磁盘。
- 类别与引擎可真实切换选中状态；对比按钮可真实切换原图、结果和并排布局。
- 上传人物照片会出现在原图框；结果框始终没有伪造图。
- 试穿、下载和历史按钮只显示可访问的提示，不调用 API、不产生任务、不下载原图冒充结果。
- 刷新清空素材和状态；离开页面释放对象 URL。
- 三个备选以 `?variant=alt` 展示真实布局变化，非截图换色。
